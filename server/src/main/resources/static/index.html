사진·동영상 원본을 별도 디스크나 Windows 공유 폴더에 둘 수 있습니다. 지정한 폴더 아래의 originals 구조를 사용하며, DB·썸네일·임시 파일 위치는 유지됩니다. 기존 원본은 자동 이동하지 않습니다.

사진은 큰 파일을 가끔 쓰지만 DB는 작은 쓰기가 잦아 디스크 속도에 민감합니다. 원본은 HDD에 두고 DB만 SSD로 옮기면 그리드·검색이 빨라집니다 (10만 장 기준 100MB 정도). 바꾸기 전에 서버를 끄고 기존 db 폴더의 photos.db·-wal·-shm 세 파일을 새 폴더로 옮기세요. 옮기지 않으면 빈 DB가 새로 만들어져 사진이 0장으로 보입니다.

그리드 스크롤은 사실상 썸네일 파일을 읽는 일이라 HDD에서 가장 느린 부분입니다. 썸네일은 원본의 17% 정도라(1TB당 약 170GB) SSD에 두기 쉽습니다. 저장하면 즉시 적용되고, 기존 썸네일은 서버가 백그라운드로 옮깁니다 — 옮기는 동안에도 사진은 계속 보입니다.

변경하면 웹은 다시 로그인해야 하고, 앱에도 새 키를 입력해야 합니다.

앨범 정리는 사진을 다시 업로드하지 않습니다. 삭제하려면 Google Photos에서 게시용 사진을 선택해 ‘휴지통으로 이동’하세요. ‘앨범에서 삭제’는 라이브러리의 사진을 지우지 않습니다.

하위 폴더까지 전부 훑습니다. 이미 있는 사진은 내용 해시로 걸러져 중복 처리되므로, 중간에 멈추거나 서버가 꺼져도 같은 경로로 다시 시작하면 이어서 진행됩니다.

복사는 사진 용량만큼 디스크를 더 씁니다 (2TB면 합계 4TB). 원본과 저장소가 같은 드라이브라면 이동이 복사 없이 즉시 끝나고 공간도 더 들지 않습니다. 이동해도 중복으로 걸러진 파일은 원본 자리에 그대로 남습니다.

임포트한 사진은 기기별 화면에서 서버 임포트로 묶입니다. 썸네일·얼굴·장면 분석은 임포트가 끝난 뒤에도 백그라운드에서 계속 처리됩니다.

재시작하면 잠시 연결이 끊겼다가 서버가 다시 뜨는 대로 자동으로 새로고침됩니다. 저장소 경로·DB 파일 위치 변경도 재시작으로 적용됩니다. 종료는 서버 프로그램만 끄며, 다시 시작하려면 서버 PC에서 실행해야 합니다.
