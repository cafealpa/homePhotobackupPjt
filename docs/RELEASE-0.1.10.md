# HomePhoto Server 0.1.10

## 주요 변경

- 얼굴 검출과 특징 추출은 기존 1600px 로컬 썸네일을 사용합니다. FACE 작업에서 네트워크 원본을 다시 읽거나 400px/원본으로 폴백하지 않습니다.
- 썸네일 생성 대기·진행·실패를 얼굴 분석 실패와 구분합니다. 1600px 파일이 없으면 시도 횟수를 소모하지 않고 60초 간격으로 재확인하며, 준비된 다른 사진은 계속 처리합니다.
- 기존 얼굴·인물 결과와 buffalo_l 모델, 640px 검출, 112px 정렬, 512차원 임베딩·그룹화 계약을 유지합니다. 이번 버전은 전체 재분석이나 결과 초기화를 추가하지 않습니다.
- 구글 포토 업로드·게시 생성·앨범·인증 갱신 오류의 원본 응답과 예외 메시지를 설정 및 작업 관리 페이지에 표시합니다. 긴 내용과 줄바꿈·URL을 보존합니다. 과거에 코드만 저장된 오류는 재시도 후 새로 발생한 오류부터 원문을 확인할 수 있습니다.
- DB 상태 저장 실패로 고립된 작업의 회수, 로컬 장면 분석 HTTP 장애의 재시도 예산 보존, 얼굴 네이티브 라이브러리 오류 표시를 보완했습니다.
- 사진 검색 모델 누락/부분 실패, 중지 상태의 재시작 보존, 연결이 끊긴 썸네일 이전 경로, 손상된 작업 이력의 복구 동작을 보완했습니다.
- 원본 저장소 단절·연결 복구 시 수신 로컬 사본과 작업 상태를 보존하고 자동 재개하는 회귀 검증을 추가했습니다.

## 설치와 호환성

- Windows x64, Java 21 기준입니다. ZIP의 `homephoto-server.jar`와 해시 이름의 `homephoto-face-runtime-*.jar`를 같은 폴더에 두세요. 런타임 파일명은 변경하지 마세요.
- 0.1.9에서 업데이트할 때 새 DB 마이그레이션이나 얼굴 초기화는 없습니다. 기존 사진·DB·설정·모델을 유지합니다.
- 썸네일 생성 자체가 실패한 사진은 썸네일 작업을 재시도하여 완료된 뒤 얼굴 분석이 재개됩니다. 완료 기록은 있지만 파일이 없는 경우 로컬 썸네일 파일과 경로를 확인하세요.
- 기존 ffmpeg 썸네일은 폭 기준으로 축소되어 세로 사진의 `1600` 파일은 긴 변이 1600보다 클 수 있습니다. 이번 버전은 기존 썸네일을 재생성하거나 크기 정책을 바꾸지 않습니다.
- 모델·ffmpeg·운영 설정·인증 파일·사진 데이터는 패키지에 포함하지 않습니다.

## 검증과 한계

- 직전 소스 변경 검증에서 서버 전체 282개 테스트와 웹 상태 테스트 7개를 통과했습니다. 릴리즈 패키지는 공식 패키징 스크립트로 생성했습니다.
- 원본 접근 금지 mock과 실제 SQLite로 로컬 입력, 생성 대기/실패, 재시작 후 재조회 간격, 시도 횟수 보존, 동영상 제외, 기존 결과 보존을 확인했습니다.
- 합성 JPEG의 EXIF 1~8, 실제 OpenCV 디코딩과 기존 얼굴 크롭 API의 정규화 좌표 호환성을 확인했습니다. ffmpeg 분기도 회전 JPEG 입력으로 확인했으며 실제 HEIC 코덱 품질 비교는 아닙니다.
- 이번 릴리즈의 별도 임시 설치 기동 검증은 완료하지 않았습니다.
- 작은 얼굴의 실제 인물 구분 품질과 네트워크·메모리·처리 시간 절감 수치는 별도 운영 사진 비교가 필요합니다. 실제 NAS/SMB 권한·단절, 운영 DB 장애와 운영 서버 교체는 검증 범위에 포함하지 않습니다.
- 기존 가져오기 스캔 오류 표시와 썸네일 이전 실패 집계의 후속 항목은 [작업 수명주기 점검 기록](https://github.com/cafealpa/homePhotobackupPjt/blob/v0.1.10/docs/PROCESS-LIFECYCLE-AUDIT.md)에 남아 있습니다.

## 운영과 롤백

업데이트 전 서버를 정상 종료하고 DB·설정·이전 JAR 쌍과 `process-monitor/state.json`을 백업하세요.
문제가 발생하면 서버를 종료한 뒤 이전 JAR 쌍과 설정을 복원하세요. DB 복원이 필요할 때는 업데이트 이후 저장한 데이터가 사라질 수 있으므로 현재 DB를 먼저 별도로 보관하세요.
GitHub 릴리즈 공개는 운영 서버의 파일 교체나 재시작을 자동 수행하지 않습니다.
