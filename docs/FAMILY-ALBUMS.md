# 가족 앨범

## 사용 흐름

Android 홈의 **이번 주 우리 가족**, **함께 찍은 하루**에서 후보를 열고 사진 선택·제외, 순서, 제목, 기록을 편집한 다음 저장한다. 첫 사진이 표지다. 저장한 앨범은 서버에 보관되어 같은 서버를 쓰는 기기에서 함께 볼 수 있고, 기존 웹 앨범 목록에도 나타난다.

- 주간 후보: 한국 시간 기준 이번 주와 지난주, 월요일~일요일.
- 하루 후보: 오늘 포함 최근 30일에 서로 다른 기기 ID가 2개 이상인 날 중 최근 8일.
- 사진 날짜는 기존 `taken_at` 메타데이터 기준이다. 촬영 정보가 없으면 기존 업로드 시각/파일 시각 정책을 따른다. 시간대 재해석이나 인물·행사 추론은 하지 않는다.
- 기기는 처음 백업한 기기 기준이며 사람의 신원과 같지 않다. 기기 정보가 없는 사진은 주간 앨범에 포함되지만 다중 기기 판정에는 세지 않는다.
- 사진만 대상이며 휴지통, 영구 삭제, 키즈노트 자료는 제외한다. 동일 원본의 SHA-256 중복 제거는 기존 자산 저장 정책을 따른다.
- 기본 추천 최대 8장: 날짜별 선택 수, 기기별 선택 수가 적은 사진을 먼저 고르고, 동률이면 즐겨찾기·촬영 시각·ID 순서로 고른다. 사진 품질 분석은 하지 않는다.
- 제목 1~100자, 기록 1,000자 이하, 선택 1~100장. 후보는 60장씩 더 불러온다.
- 늦은 백업은 후보에 반영된다. 저장한 선택·제외·순서는 자동 변경하지 않는다. 삭제된 사진은 조회에서 제외한다.
- 홈의 완성한 앨범은 최근 기간 20개를 보여준다. 그보다 오래된 저장 앨범은 기존 웹 앨범 목록에서 조회할 수 있다.

## API

기존 `X-Api-Key` 인증을 그대로 사용한다. `{kind}`는 `WEEKLY` 또는 `TOGETHER`, `{date}`는 ISO 날짜다. 주간 날짜는 해당 주 월요일로 정규화된다.

| 요청 | 동작 |
|---|---|
| GET `/api/v1/family-albums/home` | weekly, together, saved 요약 |
| GET `/api/v1/family-albums/{kind}/{date}` | 저장된 선택 또는 최초 추천, 기기별 집계 |
| GET `/api/v1/family-albums/{kind}/{date}/candidates?cursor=...` | 기간의 사진 후보 페이지 |
| POST `/api/v1/family-albums/{kind}/{date}` | 제목, 기록, 순서 있는 assetIds, revision 저장 |

요약의 `photoCount`는 **전체 후보 수**이며 저장된 선택 수가 아니다. POST 예:

```json
{"title":"가족과 보낸 한 주","note":"산책을 다녀왔어요.","assetIds":[12,8,19],"revision":0}
```

처음 저장할 때 revision=0, 이후 마지막 조회/저장 응답의 revision을 보낸다. 충돌은 409, 잘못된 기간·제목·선택은 400이다. Android는 충돌 시 편집 내용을 유지하고 다시 불러올 수 있게 한다. 조회만으로 DB를 변경하지 않는다.

## 저장 및 기존 앨범 호환

마이그레이션 6이 albums에 종류·기간·기록·revision을, album_assets에 position을 추가한다. 종류+시작일은 유일하며 수동 앨범은 종류가 NULL이다. 기존 앨범·사진 연결을 보존한다. 별도 외부 API나 사진 전송은 없다.

기존 웹의 이름 변경/사진 제거는 가족 앨범 revision도 증가시킨다. 웹에서 가족 앨범에 임의의 기간 밖 사진을 추가하는 요청은 409로 안내하며 앱 편집 화면에서 추가한다. 기존 웹 상세의 사진 정렬은 기존 타임라인 정책을 유지하고, 가족 앨범의 사용자 순서는 새 상세 API에서 제공한다.

서버와 Android 앱을 모두 업데이트해야 사용할 수 있다. 구형 서버의 404는 앱 홈에서 서버 업데이트 안내로 표시된다. 이 변경은 소스와 debug APK 검증까지만 포함하며 운영 서버 배포는 별도다.

## 검증

- 서버 전체 191개 테스트 통과. 신규 가족 앨범 테스트 6개: 기간 경계, 다중 기기, 제외 자료, 늦은 업로드, 순서·기록·충돌, 후보 페이징, 기존 테이블 마이그레이션, 추천 분산.
- Android 24개 단위 테스트 및 debug APK 빌드 통과. 저장 순서·revision·커서의 HTTP 계약 검증 포함.
- Android 34 에뮬레이터 + 로컬 fixture 서버로 홈 카드, 편집, 순서 변경, 기록 저장, 후보 추가, 저장 전 이탈 확인, 화면 회전 후 편집 유지 확인. 운영 데이터 및 실제 휴대폰 검증과는 별개다.
