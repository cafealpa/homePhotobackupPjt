## 수정 후 재점검에서 발견한 후속 항목

아래 2건은 코드 경로를 확인한 미수정 항목이다. 이번 실행에서 운영 장애를 재현했다는 의미는 아니다.

1. **P2 — 폴더 가져오기 스캔 오류가 화면에 누락될 수 있음.**
   `ImportService.scan()`의 `visitFileFailed`는 로그만 남기고,
   `postVisitDirectory`는 전달된 IOException을 무시한다.
   하위 폴더 권한 오류나 스캔 중 연결 끊김이 발생해도 `failed`/`lastError`가 갱신되지 않아
   읽을 수 있었던 항목만 처리한 뒤 정상 완료로 표시할 수 있다.
   두 경로에서 실패 건수와 오류를 기록하고, 읽을 수 있는 나머지 항목은 계속 처리하는 보완이 필요하다.

2. **P2 — 썸네일 폴더 정리의 이전 실패 건수가 남을 수 있음.**
   `ThumbnailStorage.migrateLegacyThumbs()`는 파일 처리 루프 안에서만 진행 집계를 갱신한다.
   한 번 실패한 뒤 해당 파일이 다른 경로에서 정리되어 다음 실행이 빈 폴더를 확인하면,
   성공 이벤트가 발생해도 이전 `Counts.failed`가 남아 모니터링에 계속 확인 필요로 보일 수 있다.
   실행 시작과 종료 시에도 현재 집계를 기록하는 보완이 필요하다.

## 나머지 모듈 확인 결과와 한계

- 원본 저장, 썸네일 생성, 얼굴, 장면 분석, 문서 OCR: 공통 큐 선점/실패/중지 반환과 워커 종료 후 회수 경로 확인.
- 사진 검색, 텍스트 검색: 중지 경계, 모델 준비 오류, 인덱스 저장 후 큐 확인 처리 순서 확인.
- Google Photos: 워커 예외 후 다음 실행의 영속 상태 복구와 게시 결과 불명의 UNKNOWN 전환 확인.
  UNKNOWN은 중복 게시 방지를 위해 자동 재시도하지 않는다.
- 썸네일 이전, 휴지통 자동 정리: 항목 경계 중지와 실패 기록 확인.
- 위 2건 외에 이번 재점검에서 추가로 확정한 오류는 없다. 외부 Google/Gemini 실호출,
  운영 NAS 권한/연결 장애, 운영 DB 장애, 실제 서버 교체/재시작은 이번 검증 범위에 포함하지 않았다.

운영 복구 절차는 `SERVER-MAINTENANCE.md`를 참고한다.
