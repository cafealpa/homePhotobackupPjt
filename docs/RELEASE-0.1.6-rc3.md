# HomePhoto 0.1.6-rc3

2026-10-01 릴리즈 후보. 원본 저장소 분리와 Google Photos 게시·정리 기능을 포함한다.
이전 rc2 이후의 로컬 사진·얼굴 벡터 검색 및 MCP 촬영 기간 검색 개선도 함께 포함한다.

## 변경 내용

- 원본 파일 접근을 StorageAdapter로 분리하고, DB·썸네일 위치와 원본 저장소 위치를 각각 설정할 수 있게 했다. 기존 원본은 자동 이동하지 않는다.
- Google Photos에 별도 1600px JPEG를 게시하고, 기존 촬영일·GPS 정보를 EXIF에 기록한다. 원본과 기존 썸네일은 수정하지 않는다.
- 별도 Desktop OAuth 인증 파일, 영속 게시 큐, 재시도·취소·결과 불명 확인 흐름을 추가했다. 기본 게시와 새 백업 자동 게시 설정은 꺼짐이다.
- 홈서버 게시 사진을 **HomePhoto · 1600px 게시용** 앨범에 모은다. 신규 게시에는 앨범을 지정하고, 기존 완료 항목은 사진을 다시 업로드하지 않고 앨범에 연결한다.
- 설정의 완료·취소 게시 이력을 기본으로 접어 두었다. 진행·실패·결과 확인이 필요한 작업은 바로 표시한다. 완료 기록은 재게시 방지를 위해 보관한다.
- 로컬 의미 검색·다중 얼굴 인덱스와 검색 서비스 시작·중지 및 상태 조회를 추가했다. 검색 서비스 설치와 모델 준비는 별도 절차를 따른다.
- MCP에 촬영 기간 검색, 날짜별 집계와 갤러리 페이지 이동을 추가했다.
- 배포 JAR의 실행 클래스를 서버로 명시해 인증·앨범 정리 명령 도구의 `main` 함수와 충돌하지 않도록 했다.

## 업데이트

이 ZIP은 **기존 설치의 JAR 교체용**이다. Java 21 이상과 기존 실행 스크립트를 사용한다.
ZIP의 `homephoto-server.jar`와 SHA256 파일을 확인한 뒤 다음 순서로 적용한다.

1. 운영 서버를 정상 종료하고 현재 JAR와 DB·설정 백업을 보관한다.
2. `homephoto-server.jar`만 새 파일로 교체한다. 기존 `data`, `config`, 인증 파일과 워커 설치는 유지한다.
3. 기존 시작 방식으로 서버를 실행한다. 설정 → 서버 정보의 버전이 **v0.1.6-rc3**인지 확인한다.
4. 설정의 Google Photos 상태와 완료 이력 접힘, 기존 사진 조회를 확인한다. 보존된 게시 사용 설정이 켜져 있다면 대기 작업도 처리될 수 있으므로 적용 전에 대기 건수를 확인한다.

DB migration 2는 Google Photos 게시 이력 테이블을 추가한다. 원본 경로를 일괄 변경하지 않는다.
이전 서버에 migration 2가 이미 적용돼 있다면 새 migration은 없다.
원본 저장소 경로를 바꾸거나 기존 원본을 이동하는 작업은 릴리즈 적용과 별도로 진행한다.

Google Photos 토큰 옆의 `<토큰 파일명>.albums.json`은 전용 앨범 상태 파일이다.
인증 파일을 옮길 때 함께 보관하며, 게시 이력을 지우거나 토큰을 재발급해 초기화하지 않는다.
이미 Google Photos에 원본이 있다면 게시용 JPEG도 별도 사진으로 보인다. 기존 원본과 자동 비교는 지원하지 않는다.
게시용 사진을 정리하려면 전용 앨범에서 선택해 **휴지통으로 이동**한다. **앨범에서 삭제**만 하면 라이브러리에 남는다.

문제가 생기면 서버를 정상 종료한 뒤 백업 JAR와 기존 실행 설정으로 복원한다.
DB 복원이 필요하면 릴리즈 적용 전 백업을 사용하며, 게시 완료 이력이 사라져 재게시되지 않도록 대기 작업을 확인한다.

## 검증 범위와 남은 항목

- 지정된 `build-jar.ps1`로 전체 서버 테스트 **123건 통과**와 실행 JAR 빌드를 확인했다. 실패·오류·건너뜀은 0건이며, JAR manifest의 실행 클래스와 빌드 버전도 확인했다.
- 배포 JAR를 Java **21.0.9**로 루프백·임의 포트·격리 저장소에서 실행했다. 서버 정보 API의 `0.1.6-rc3`, 설정 조회 성공과 Google Photos 비활성·빈 큐를 확인했다. 운영 설치에서의 기동 검증은 포함하지 않는다.
- Google Photos의 소량 실계정 게시 성공은 사용자가 확인했다. 기존 게시 사진 10장의 전용 앨범 연결도 확인했다. 추가 사진 업로드나 자동 삭제는 이 릴리즈 준비에서 실행하지 않는다.
- 실제 UNC 공유 접근, Google Photos의 촬영일·GPS·방향 등 항목별 표시 검증, 공개 MCP의 실제 클라이언트 연결 검증은 보류 상태다.
- ZIP에는 운영 사진·DB·설정·OAuth 인증 파일, Java·ffmpeg·얼굴 인식 실행 파일·Python 검색 환경을 포함하지 않는다. 기존 설치 구성이나 별도 설치 절차를 사용한다.
- 이번 요청은 로컬 배포 파일과 커밋까지 준비하며, 운영 설치 교체는 별도 작업이다.
