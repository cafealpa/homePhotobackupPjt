# 사진 홈의 다시 보기

사진 홈은 사용자가 사진을 고르기 전에 감상할 수 있는 하루치 사진 묶음을 제공한다.
SQLite와 기존 촬영일·즐겨찾기·인물·문서 분석 결과를 이용하며, 요청 중 새 AI 분석을 실행하지 않는다.

## 선정

- 서울 날짜 기준 첫 조회 때 최대 세 묶음을 생성한다. 가족 기기들이 같은 구성을 공유한다.
- `ANNIVERSARY`: 90일보다 오래된 날 중 과거 오늘 전후 7일에 해당하며 유효 사진이 4장 이상인 하루.
- `REDISCOVER`: 90일보다 오래되고 유효 사진이 4장 이상인 하루. 같은 날의 기념일 카드와 중복하지 않는다.
- `RECENT`: 오늘을 포함한 7일의 사진. 후보가 없으면 생성일 기준 `ADDED` 카드로 대체한다.
- 과거/최근 촬영일은 기존 TakenAtResolver 계약에 따라 `FILENAME`, `EXIF`를 인정한다.
  `FILE_MTIME`, `UPLOAD_TIME`은 과거 추억의 근거로 삼지 않는다.
- 삭제·영구삭제·키즈노트·동영상·DOCUMENT 분류 사진은 제외한다. 미분석 사진은 포함한다.
- 지난 30일에 추천하지 않은 날을 먼저 고른다. 후보가 부족하면 가장 오래전에 추천한 날을 재사용한다.
  추천 기록은 실제 열람 이력이 아니다.
- 날짜 점수는 즐겨찾기 사진 수(최대 4) × 4 + 이름을 붙인 인물 사진 수(최대 4) × 2이다.
  기념일은 오늘과의 날짜 차이를 점수보다 우선한다. 동점은 서울 날짜와 후보 날짜로 안정적으로 분산한다.
- 최대 12장을 고른다. 날짜별 분산 → 같은 백업 기기/15분 구간 분산 → 즐겨찾기·인물 가점과 인물 반복 감점 순이다.
  백업 기기는 실제 촬영 기기나 함께 외출했다는 증거가 아니다. 이미지 유사도를 판별하지는 않는다.
- 선정 결과는 촬영 시간순으로 저장하며 표지는 가점이 높은 사진이다.

## 저장과 API

마이그레이션 8이 `memory_sets`, `memory_photos`를 추가한다. 빈 날도 EMPTY 행으로 저장한다.
서버 재시작과 추가 백업은 당일 구성을 바꾸지 않는다. 삭제·문서 판정은 조회 시 다시 적용한다.
구성이 줄어도 당일 새 사진으로 채우지 않는다. 신규 사진은 다음 날 선정에 반영한다.

| API | 역할 |
| --- | --- |
| GET /api/v1/memories/home | 오늘의 추억과 최근 저장한 추억 앨범 20개 |
| GET /api/v1/memories/{id} | 유효 사진을 선정 순서대로 감상 |
| POST /api/v1/memories/{id}/album | title, assetIds로 순서와 제목을 지정하여 원자적으로 저장 |
| GET /api/v1/memories/albums/{id} | 저장한 앨범을 사용자 지정 순서로 조회 |

앨범은 기존 albums/album_assets를 사용하며 story_kind는 NULL이다. WEEKLY/TOGETHER와 충돌하지 않는다.
첫 사진이 앨범 표지이고 같은 묶음의 저장 재시도는 기존 앨범을 반환한다. 기존 앨범을 덮어쓰지 않는다.
사용자가 해당 앨범을 삭제한 경우에는 다시 저장할 수 있다. 사진 원본은 복사하거나 변경하지 않는다.
추억 메타데이터와 앨범 연결은 유지하며 자동 정리는 하지 않는다.

## Android

홈 카드 → 좌우 넘기기 감상 → 선택적으로 제목/사진/순서를 편집하여 앨범 저장.
기존 가족 앨범은 홈의 간직한 앨범에서 접근한다. 홈 스크롤은 감상 후 복귀해도 유지한다.
앱 복귀 시 오늘 구성을 갱신하며, Retrofit 프록시 대신 서버 연결 설정을 Compose effect key로 사용한다.
미지원 서버의 404, 통신 오류, 빈 추억 목록을 구분한다. 추억을 제공할 수 없을 때 최근 사진을 보여준다.

## 검증 및 한계

MemoryServiceTest는 실제 임시 SQLite에서 날짜 경계, 문서/삭제 필터, 일별 고정, 추천 순환,
사진 다양성, 파일명 촬영일, 저장 원자성/멱등성/순서/표지와 기존 앨범 호환성을 검증한다.
Android MemoryApiTest는 날짜/사진 순서, 추억 ID와 앨범 ID 구분, 저장 요청, 404/503 구분을 검증한다.
Android 에뮬레이터 화면 점검은 합성 사진과 로컬 테스트 응답을 사용하며 운영 서버 검증과 구분한다.
대규모 실제 라이브러리의 선정 품질/응답시간은 배포 후 별도 확인 대상이다.
