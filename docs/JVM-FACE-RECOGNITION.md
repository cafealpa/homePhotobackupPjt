# JVM 얼굴 인식 전환

얼굴 검출·특징 추출은 Spring 서버의 `FaceWorker`가 ONNX Runtime Java와 OpenCV Java로 수행한다. Python 얼굴 워커 및 관련 실행/빌드/패키징 경로와 구형 결과 제출 API는 제거했다. 사진 의미 검색과 얼굴 벡터 검색도 JVM으로 이전했다. [JVM 벡터 검색 전환](JVM-VECTOR-SEARCH.md)을 참고한다.

## 이전 얼굴 인식 전환의 1회 초기화 (마이그레이션 5)

2026-10-08 검색 JVM 전환은 DB 초기화를 추가하지 않는다. 아래는 기존 마이그레이션 5의 동작 기록이다.

사용자 요청에 따라 DB 마이그레이션 **5**에서 기존 `faces`, `persons`와 FACE 작업을 삭제하고, 휴지통·영구 삭제 항목을 제외한 모든 PHOTO에 FACE 작업을 새로 등록한다. 기존 이름, 묶음, 숨김 결과도 초기화된다. 사진 원본, 썸네일, 캡션, 앨범, 백업 큐는 삭제하지 않는다.

초기화와 버전 기록은 같은 트랜잭션이다. 새 서버의 첫 시작에서 실행되며 성공 후에는 재시작해도 반복하지 않는다. 이력 5를 임의로 지우면 다시 초기화되므로 삭제하지 않는다. 모델이 없어도 초기화는 수행하고 작업을 PENDING으로 대기시킨다. 운영에 적용하기 전에 이 변경을 포함한 서버 JAR를 배포해야 하며 소스 수정만으로 실행 중인 DB가 변경되지는 않는다.

얼굴 벡터 검색 서비스가 켜져 있으면 정기 전체 동기화에서 기존 검색 인덱스의 불필요한 얼굴을 삭제하고 새 벡터로 갱신한다(기본 5분). 검색 서비스가 꺼져 있는 동안 로컬 검색 인덱스 파일은 남지만 새 DB와 일치하지 않는 검색 결과는 서버에서 제외한다.

## 모델과 설정

두 파일을 준비한다. 기존 InsightFace buffalo_l 모델을 재사용하며 학습을 새로 할 필요는 없다.

| 파일 | SHA-256 |
| --- | --- |
| det_10g.onnx | 5838f7fe053675b1c7a08b633df49e7af5495cee0493c7dcf6697200b85b5b91 |
| w600k_r50.onnx | 4c06341c33c2ca1f86781dab0e829f88ad5b64be9fba56e56bc9ebdefc619e43 |

설정 화면의 **얼굴 인식 → 모델 폴더**에 두 파일이 있는 전체 경로를 입력하고 저장한다. 빈 경로는 실행 폴더의 `models/buffalo_l`, 서버 실행 계정의 `~/.insightface/models/buffalo_l` 순서로 탐색한다. 모델은 JAR에 포함하지 않는다. 다른 모델이 섞이지 않도록 파일 해시를 검증한다.

기본 설정은 `homephoto.face.enabled: true`이다. 웹의 **얼굴 인식 사용**을 끄면 진행 중인 사진을 마친 후 쉬고, 켜면 대기 작업을 이어간다. 변경은 `config/application.yml`에 저장된다. 모델 누락·손상은 화면에 원인을 표시하고 60초 후 다시 확인하며 사진을 모두 FAILED로 만들지 않는다.

운영 PC의 기존 Python 얼굴 EXE/worker.py 프로세스는 종료한다. 새 서버는 구형 워커의 작업 클레임/결과 반영 API를 제공하지 않는다. 구형 검색 가상환경은 JVM 검색 전환 확인 후 정리할 수 있다. 얼굴 검출 모델 파일은 유지한다.

## 중간 결과와 처리 방식

- 전용 단일 워커와 ONNX 연산 스레드 2개로 추론한다. 서버의 안전 종료 시 활성 작업으로 집계된다.
- 각 사진 분석을 DB에 저장한 다음 미분류 얼굴을 기존 인물과 코사인 유사도 0.55 이상일 때 연결한다. 일치 항목이 없으면 새 인물 묶음을 만든다. 얼굴이 한 번만 나와도 표시한다.
- 새 묶음은 영속 DB에서 번호를 정하며 전체 얼굴을 다시 번호 매기지 않는다. 이후 사용자가 바꾼 이름·이동·합치기·숨김은 자동 재클러스터링으로 덮어쓰지 않는다.
- 이 방식은 기존 전체 DBSCAN과 동일한 알고리즘이 아니다. 입력 순서에 따라 묶음이 달라질 수 있고 오분류는 인물 화면의 합치기/제외로 수정한다. 자동 일치는 본인 확인이나 확정 라벨이 아니다.
- 인물 화면은 5초마다 분석 완료/대기/실패와 인물 목록을 갱신한다. 다른 화면·백그라운드 탭·인물 합치기 중에는 갱신을 미룬다.
- 네트워크 원본 읽기 오류는 큐로 돌려놓고 잠시 쉰다. 디코딩 등 개별 사진 오류는 기존 최대 3회 재시도 정책을 따른다.

## 검증

공개 InsightFace 샘플 `t1.jpg`를 기존 Python 0.7.3 CPU와 JVM CPU에서 실행했다. 두 구현 모두 얼굴 6개를 검출했고 각 특징 벡터 코사인 유사도는 0.999998 이상이었다. 이는 해당 샘플의 추론 호환성 검증이며 전체 운영 사진의 정확도·처리량을 보장하는 측정은 아니다.

`faceEngineSmoke` Gradle 태스크는 명시한 모델, 샘플 사진, Python 기준 JSON만 읽고 DB에 접근하지 않는다. 운영 DB 초기화 없이 임시 DB 회귀 테스트로 1회 마이그레이션, 인물 중간 표시, 수동 묶음 보존, 비활성 및 모델 누락 동작을 확인한다.

완성된 bootJar도 별도 임시 DB와 loopback 포트에서 실행해 공개 샘플 업로드 → FACE 완료 → 얼굴 6개/인물 묶음 6개 조회 → 안전 종료(exit 0)까지 확인했다. 운영 서버의 DB·프로세스를 이용한 검증은 아니다.

참고: [ONNX Runtime Java](https://onnxruntime.ai/docs/get-started/with-java.html), [InsightFace 모델](https://github.com/deepinsight/insightface/tree/master/model_zoo). 기존 모델 사용 조건은 언어 전환으로 변경되지 않는다.
