# 안드로이드 앱 UI 가이드

> 작성: 2026-08-19. 시스템 설계는 [DESIGN.md](DESIGN.md), 이 문서는 **안드로이드 앱의 화면·디자인 의도**만 다룬다.
> Claude Design 등 외부 디자인 도구에 컨텍스트로 넘기는 기준 문서.

## 1. 한 줄 정의

가족이 쓰는 **개인 사진 백업 앱**. 폰의 사진·동영상을 집 서버로 올리고, 서버에 쌓인 사진을
타임라인·인물별로 본다. 클라우드 앨범 앱(Google Photos 등)과 비슷하지만, 서버가 집에 있고
사용자는 가족 몇 명뿐이다.

## 2. 디자인 원칙

1. **사진이 주인공** — 크롬(바·배경·카드)은 채도 낮은 중립색, 포인트 색은 틸 하나만.
   다이내믹 컬러(Material You)는 쓰지 않는다(사진 색감과 충돌).
2. **한국어 기본, 짧은 문장** — 라벨은 명사형("백업", "인물"), 안내는 존댓말("~할 수 없어요").
   기술 용어(해시·큐·워커)는 화면에 노출하지 않는다.
3. **상태가 항상 보인다** — 백업은 백그라운드에서 돌기 때문에 "지금 뭘 하고 있는지,
   몇 개 남았는지, 뭐가 실패했는지"를 한 화면에서 알 수 있어야 한다.
4. **가족 구성원 누구나** — 아이콘만으로 뜻을 전달하지 않는다(텍스트 라벨 병기).
   터치 타깃 48dp 이상.
5. **오프라인/서버 다운 대비** — 서버가 꺼져 있어도 앱이 깨지지 않고, 원인을 쉬운 말로
   알려주고("서버에 연결할 수 없어요"), 재시도 버튼을 준다.

## 3. 정보 구조와 네비게이션

최상위는 **탭 4개** (현재 `TabRow`, 하단 `NavigationBar`로 바꾸는 것을 검토 중).

```
[사진] ── 타임라인 그리드 ─▶ 전체화면 뷰어(좌우 스와이프, 삭제)
[인물] ── 인물(클러스터) 그리드 ─▶ 인물 상세 그리드 ─▶ 전체화면 뷰어
                                   └─ 이름 붙이기 다이얼로그
[백업] ── 요약 카드 + 진행 상태 + 버튼 ─▶ 실패 이력 / 스킵된 사진 관리
[설정] ── 서버 주소·API 키·기기 이름 / 자동 백업 옵션
```

뒤로가기는 시스템 백 버튼(`BackHandler`)으로 처리. 전체화면 뷰어는 순흑 배경에
오버레이 텍스트(흰색)만 쓴다.

## 4. 화면별 역할과 상태

| 화면 | 파일 | 핵심 요소 | 꼭 다뤄야 할 상태 |
|---|---|---|---|
| 사진(타임라인) | `ui/TimelineScreen.kt` | 월 헤더 + 정사각 썸네일 그리드(3~4열, 틈 2dp), 새로고침 | 로딩 / 빈 목록(첫 사용) / 서버 오류 / 더 불러오기 실패 |
| 인물 | `ui/PeopleScreen.kt` | 대표 얼굴 썸네일 3열 그리드, 이름·사진 수 | 로딩 / 인식된 인물 없음(워커 미설치 안내) / 오류 |
| 인물 상세 | `ui/PeopleScreen.kt` | 제목(이름 또는 "이름 없음"), 이름 붙이기, 4열 그리드 | 이름 없음 / 저장 실패 |
| 백업 | `ui/BackupScreen.kt` | 요약 카드(발견·완료·대기·실패), 진행 중 표시(단계·n/m·현재 파일), 지금 백업/중지, 실패 이력 카드 | 권한 없음 / 대기 / 스캔 중 / 업로드 중 / 완료 / 오류 / 실패 이력 있음 / 스킵 있음 |
| 설정 | `ui/SettingsScreen.kt` | 서버 주소·API 키·기기 이름 입력, 저장, 자동 백업 토글·조건 | 저장 성공 피드백 / 연결 테스트 결과 (추가 예정) |
| 전체화면 뷰어 | `ui/AssetBrowsing.kt` | 페이저, 파일명·촬영일, 삭제(휴지통 이동) 확인 다이얼로그 | 동영상(재생 미지원 안내) / 삭제 확인 |

공용 조각(컴포넌트 후보 — 현재는 화면 안에 인라인):
- `ThumbCell` 정사각 썸네일(+동영상 배지) — `AssetBrowsing.kt`에 있음
- 오류 안내 블록(제목 + 설명 + 다시 시도 버튼) — 타임라인·인물에서 반복
- 화면 제목 행(제목 + 우측 텍스트 버튼) — 모든 탭에서 반복
- 상태 카드(라벨: 값 목록) — 백업 요약

## 5. 디자인 토큰 (코드 기준: `ui/theme/`)

| 항목 | 값 | 파일 |
|---|---|---|
| 포인트 색 | 틸 `#00696B`(라이트) / `#4FD8DA`(다크) | `Color.kt` |
| 배경/표면 | `#FAFAF8`(라이트) / `#121414`(다크). 뷰어만 `#000000` | `Color.kt` |
| 오류 | M3 기본 레드 `#BA1A1A` | `Color.kt` |
| 오버레이 텍스트 | 흰색 / `#BDBDBD` / 경고 `#FFD54F` | `Color.kt` |
| 타이포 | 시스템 기본 글꼴. headlineSmall 24/SemiBold, titleMedium 16/SemiBold, bodyMedium 14, bodySmall 12 | `Type.kt` |
| 모서리 | 카드·다이얼로그 12dp, 버튼·칩 8dp, 썸네일 0 | `Theme.kt` |
| 간격 | 화면 여백 16, 섹션 12, 항목 8, 그리드 틈 2 | `Theme.kt` `HomePhotoSpacing` |
| 다크 모드 | 시스템 설정을 따름. 별도 토글 없음 | `Theme.kt` |

규칙: 화면 코드에서 `Color(0x...)`, `.dp` 숫자 하드코딩을 새로 만들지 말고
`MaterialTheme.colorScheme.*`, `MaterialTheme.typography.*`, `HomePhotoSpacing.*`을 쓴다.
오버레이(사진 위 텍스트)만 `HomePhotoColors.Overlay*` 직접 사용 허용.

## 6. 문구 톤

- 버튼: 동사 명령형 2~4글자 — "저장", "다시 시도", "지금 백업", "중지"
- 오류 제목: "~할 수 없어요" + 본문에 원인과 할 일 (`data/ErrorMessages.kt`가 변환)
- 숫자: "백업 완료: 1,234개" 처럼 단위 붙임. 진행률은 "업로드 123/456"

## 7. Claude Design에 요청할 때

- 스택 명시: "Jetpack Compose Material3. `HomePhotoTheme` 토큰만 사용, 새 색 하드코딩 금지"
- 단위: 화면 하나 + 상태 변형(위 표의 상태 열) 세트로 요청
- 우선순위: ① 백업 화면(상태가 가장 많음) ② 타임라인 빈/오류 상태 ③ 하단 내비게이션 전환
- 산출물은 Compose 코드로 옮기는 것이 목표이므로, HTML보다 구조·간격·색 역할이 드러나는
  목업을 요청한다
- 현재 화면 스크린샷은 `docs/screens/`에 둔다 (추가 예정)
