# HomePhoto Server 0.1.9

## 주요 변경

- 대시보드 모니터링에서 원본 저장, 썸네일, 얼굴 인식, 장면 분석, 문서 OCR, 검색 인덱싱, Google Photos 전송, 가져오기, 썸네일 폴더 이전·정리, 휴지통 정리의 13종 작업을 관리합니다.
- 작업 대기, 자원 사용 대기, 실행, 재시도 대기, 중지 중, 중지 완료, 재시작, 완료, 오류 상태를 구분하고 현재 항목과 대기 이유를 표시합니다. 전체량을 알 수 없을 때는 0으로 표시하지 않고 미확정으로 표시합니다.
- 중지는 새 작업과 자동 재시도를 막고 현재 처리를 안전한 경계에서 정리합니다. 재시작은 기존 실행이 끝난 뒤 남은 작업을 재개합니다.
- 서버 재기동 후에도 중지 상태, 오류, 재시도 시각, 가져오기 설정과 진행 기록을 보존합니다. 실패 작업은 자동으로 초기화하지 않고 명시적인 재시도로 처리합니다.
- 썸네일 변환, 얼굴 추론, OCR 이미지 준비와 임베딩의 CPU 동시 실행을 기본 2개로 제한합니다. 원본 수신·저장은 이 한도에 묶이지 않습니다.
- 사진 홈에 일별 추억 선정과 앨범 저장 기능을 추가했습니다.

## 설치와 운영

- Windows x64, Java 21 기준입니다. ZIP의 `homephoto-server.jar`와 해시 이름의 `homephoto-face-runtime-*.jar`를 같은 폴더에 두세요. 런타임 파일명은 변경하지 마세요.
- 기존 사진, DB, 설정, 모델을 유지하여 업데이트합니다. 최초 기동 시 마이그레이션 8이 추억 선정 기록용 `memory_sets`, `memory_photos` 테이블을 추가합니다.
- `homephoto.background-cpu-tasks`로 CPU 작업 동시 실행 한도를 설정할 수 있습니다(기본 2, 범위 1–64, 서버 재시작 후 적용).
- 표시용 진행 기록은 5초마다 저장합니다. 비정상 종료 직전 기록은 저장 주기만큼 뒤처질 수 있으며 실제 완료 여부는 DB와 파일을 다시 확인합니다.
- 중단된 가져오기는 중지 상태로 복구됩니다. 모니터링에서 시작하면 원본을 다시 스캔하고 기존 저장 결과를 확인하며 재개합니다.
- 자세한 내용은 [작업 모니터링과 개별 제어](https://github.com/cafealpa/homePhotobackupPjt/blob/v0.1.9/docs/SERVER-MAINTENANCE.md)를 참고하세요.

## 검증과 롤백

- 전체 서버 테스트 252개, 패키징, 임시 서버 브라우저 제어, 재기동 후 13종 중지 상태 보존을 확인했습니다.
- 업데이트 전 정상 종료 후 DB·설정·기존 JAR 쌍과 `process-monitor/state.json`을 백업하세요. 문제 발생 시 서버를 종료하고 이전 JAR 쌍과 설정을 복원하세요. DB 백업 복원이 필요하면 업데이트 이후 저장한 데이터가 사라질 수 있으므로 먼저 현재 DB를 별도로 보관하세요.
- GitHub 릴리즈 공개는 운영 서버의 파일 교체나 재시작을 자동 수행하지 않습니다.
